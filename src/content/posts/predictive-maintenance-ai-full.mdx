Integrating Artificial Intelligence and Machine Learning models into traditional enterprise environments requires more than just making an API call. It demands a rigorous approach to fault tolerance, observability, and system design. 

To bridge the gap between data science and production engineering, I built a full-stack **Predictive Maintenance Platform** as a capstone project for my AI/ML post-graduate studies. The system is designed to analyze engine telemetry data and predict potential failures using an AI model hosted on Hugging Face, all wrapped in a resilient enterprise backend.

---

## The Business Problem

Unexpected engine failures create significant financial and operational risks for vehicle owners, fleet operators, and manufacturers. Breakdowns lead to expensive repairs, unplanned downtime, and in some cases, severe safety hazards. 

Historically, maintenance has been reactive (fixing what is broken) or strictly schedule-based (replacing parts whether they need it or not). Predictive maintenance solves this by utilizing continuous engine sensor data to anticipate failures *before* they occur, allowing maintenance to be scheduled proactively.

---

## The Objective

The core objective of this project is to build a machine learning model capable of analyzing operating parameters—such as RPM, pressures, and temperatures—to classify whether an engine is operating normally or requires immediate maintenance. Because these parameters are broadly consistent across engine types, the resulting model is applicable to everything from automotive engines to compact machinery and generators.

However, a model is only valuable if it is accessible. Beyond simply training the algorithm in a Jupyter notebook, the goal is to deliver a live, working deployment. 

By transitioning this model into a live enterprise application supported by an automated CI/CD pipeline, the platform helps stakeholders:
* Reduce unplanned breakdowns and associated repair costs.
* Improve vehicle performance and extend engine lifespan.
* Optimize maintenance schedules to minimize operational downtime.
* Provide data-driven insights to manufacturers and fleet operators for better decision-making.

### Architectural Flow & Approach

The diagram above illustrates a resilient, event-driven approach to AI integration:

*   **Telemetry Ingestion:** The React UI client submits real-time engine sensor data to the Spring Boot API. The API persists the raw telemetry to a PostgreSQL database for auditing and future model retraining.
*   **The Resilience Layer:** To protect the enterprise backend from external AI service failures, the call to Hugging Face is wrapped in Resilience4j patterns. 
*   **Asynchronous Inference:** The system makes non-blocking calls to the Hugging Face ML endpoint to compute the engine's failure probability, allowing the backend to remain highly responsive.

## Low-Level Design & Key Implementation

Rather than relying heavily on a service mesh, I chose to implement resilience at the application level. This grants the JVM much finer control over how threads behave when external ML endpoints experience latency spikes.

### The Application-Level Circuit Breaker

Using Resilience4j, the API call to Hugging Face is wrapped to fail fast if the model goes down, preventing cascading failures across the enterprise architecture.

```java
@Service
public class PredictiveMaintenanceService {

    @CircuitBreaker(name = "huggingFaceInference", fallbackMethod = "fallbackPrediction")
    @TimeLimiter(name = "huggingFaceInference")
    @Bulkhead(name = "huggingFaceInference", type = Bulkhead.Type.THREADPOOL)
    public CompletableFuture<EngineStatus> getFailureProbability(TelemetryData data) {
        // Asynchronous call to Hugging Face ML Endpoint
        return mlClient.predict(data);
    }

    // Graceful degradation when AI is unavailable
    public CompletableFuture<EngineStatus> fallbackPrediction(TelemetryData data, Throwable t) {
        log.warn("ML Endpoint unavailable. Defaulting to historical threshold rules.", t);
        return CompletableFuture.completedFuture(ruleBasedEvaluation(data));
    }
}
```

### The React Frontend Integration

The frontend was built to consume these resilient endpoints efficiently, ensuring the UI remains responsive even if the backend is executing its fallback logic. 

```javascript
// TelemetryDashboard.jsx
import React, { useState, useEffect } from 'react';

export default function TelemetryDashboard({ engineId }) {
  const [status, setStatus] = useState(null);

  useEffect(() => {
    const fetchStatus = async () => {
      try {
        const response = await fetch('/api/v1/engines/${engineId}/predict');
        const data = await response.json();
        setStatus(data);
      } catch (error) {
        console.error("Failed to fetch engine status", error);
      }
    };
    
    // Poll for real-time inference updates
    const interval = setInterval(fetchStatus, 5000);
    return () => clearInterval(interval);
  }, [engineId]);

  return (
    <div className="dashboard-card">
      <h3>Engine Health: {status?.condition || 'Analyzing...'}</h3>
      <p>Failure Probability: {status?.probability}%</p>
    </div>
  );
}
```

## Challenges Faced

1.  **Handling Inference Latency & Thread Exhaustion:** Initial load testing revealed that network latency to the Hugging Face endpoint was tying up worker threads. Analyzing JVM thread dumps within APM tools like Dynatrace and AppDynamics showed the backend struggling under concurrent loads. Implementing the Resilience4j Threadpool Bulkhead isolated the inference calls, preventing thread starvation in the main application.
2.  **Garbage Collection Overhead:** The high volume of JSON telemetry data being ingested and serialized caused frequent minor GC pauses. Analyzing GC logs allowed me to tune the JVM heap parameters and garbage collection strategy to accommodate the bursty nature of the sensor data streams without stalling the application.
3.  **Graceful Degradation:** Deciding *what* the application should do when the AI is down. We implemented a fallback mechanism that evaluates the telemetry against hardcoded historical thresholds if the ML model is unreachable.

By treating the AI model as an unreliable external dependency and protecting the JVM with strict resilience patterns, we can safely integrate intelligent capabilities into critical enterprise systems.
